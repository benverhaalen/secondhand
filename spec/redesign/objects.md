# Pushed pages about one object

This is a design specification, not an implemented or visually verified redesign. Only this file is changed. Code observations are from the working tree at base `1107a97a`, read on 2026-11-15. Another session is changing screens, so file:line references identify the observed expression as well as its location. Recheck expressions before building.

The person is clearing their own things or buying used. They enter from a photo, a decision, capture, search or a link. They need to recognise the subject, understand its current position and take its next action without first reading a dashboard. They may return several times while a job runs. A mistake can change the wrong object or send an unapproved price. Pickup details must remain private until approved, and a failed external action must remain visibly unresolved.

Success: open an object from its normal entry, recognise it, see the relevant valuation and one next action, inspect a detail, return to the same place, and complete or leave the task with its real state preserved. The same journey must work with incomplete data, bad signal, a long title, a large amount, the largest text setting and Reduce Motion.

2. **Hero and identity in a Stack.** Item and Listing use PhotoPager. Product and Worth use Row with Photo and identity. 3. **Valuation block.** A Stack of the most relevant Amount or Range, a PriceRange where useful, and one ListRow to its basis. Block is a domain container, not a new filled card. Product and Worth emphasise the sold range; Listing emphasises total payable. Item emphasises the moment's money or current question. Want emphasises the chosen delivered ceiling, with sold range quieter. Gone by shows a conditional plan estimate, never calls it market value.
4. **One primary action.** Use FootButton to enter the next task, Approve to commit an external act, or the one DecisionCard's primary. Place it in the content when it fits in the first 844-point view. With a full photo or required decision context pushing it out, put it in Screen.foot, with no duplicate in content. 5. **One List of topic rows.** Current summaries stay visible as row values. Full forms, timelines and charts sit behind chevrons. Topic spacing comes from Section; rows do not acquire their own cards. No empty section headings.
6. **Less frequent subject actions.** ActionRow in List at the end or one row opening a focused subject-actions page. Keep the complete available action set reachable. A destructive action never becomes the black primary.

One thing stands out per page/moment, named below. A large photo establishes which item; do not add a second giant title and multiple 50-point amounts. Where an amount is the focal thing, use compact Photo rather than a second hero. A live urgent decision may take the one state field. Ordinary facts are flat. Stack for reading order, rows for comparing like things, no pile on an individual object page. A room's many objects are a Grid, not layered decision cards.

### Shared interaction contract

- **Push/back:** a disclosure pushes deeper and preserves the parent. Back, iOS edge swipe and Android Back pop to the actual origin with offset and selection preserved. No haptic for navigation. Cold links need a real tab root underneath: Item/Worth to Sell, Product/Listing/Want to Buy, Gone by to Sell. Back never reverses a sale. A sheet first dismisses, then Back leaves the page.
- **Motion names and actual durations:** `app/src/ui/motion.ts` gives `press` and `openItem` as `spring`, with no fixed duration; do not invent a duration for them. `press.tsx` currently supplies 150 ms press-in and 300 ms release spring parameters from tokens, scaling 0.97. `sheet` is 300 ms in; `select` is 200 ms and is the existing routed-sheet exit timing; `fieldsFill` is 150 ms; `tileMoves` is 200 ms. Native push/pop are platform transitions, with the frontend panel budget of 200 to 300 ms, not a named `nativePush` export. Do not misuse `openItem` for a different subject or claim native-stack timing is currently configured.
- **Feedback:** use existing Press through the listed primitives. Buttons darken/give way on press-in, release springs back; rows highlight; disabled controls do not act. Current Press also scales rows and bar buttons. Earlier brand asks all pressables to give way; keep the shared implementation here rather than inventing per-page exceptions to match the later vendor's no-scale rows. No duplicate press wrappers.
- **Haptics:** none for Back, disclosure, photo paging, reading, typing, scrolling or initial load. One light impact on a committed reversible choice or deliberate approval. One success notification when a user-requested external operation is confirmed; one warning on its confirmed failure, once, not on each render or poll. Do not vibrate for every partial result. A cancelled press produces no haptic. These are specified outcomes, not a claim every current part fires them.
- **Short sheets:** existing Sheet has no detents, no swipe-to-dismiss and no keyboard avoidance. Use content-sized height only for genuinely short non-keyboard choices, with explicit Done/Cancel plus scrim dismissal. A two-step task is a routed task, not stacked local sheets.
- **Tall tasks:** RouteSheet has one expanded, screen-capped size and its own scroll; no medium detent. Plan/Post use this today. Close, scrim and handle dismissal return to the exact object. Edge swipe must not accidentally pop the object below the sheet. Protect unsaved form changes; after an acknowledged send, closing never cancels the external job.
- **External sites:** SiteLink or the primary Open on site opens the actual listing URL through the platform URL handler. Returning resumes this object and rechecks availability. Handle unavailable URL, missing URL and open failure inline with Retry. Payment stays on the site. No success haptic merely for opening a browser.
- **Undo:** UndoToast lasts the existing five seconds and reverses only a reversible acknowledged action. It must not erase or replace the page's only remaining primary access; keep that access in content while a toast occupies the foot. An irreversible action uses a consequence and explicit Approve, never a fake Undo.
