# Wiring the app to the server

Drafted 2026-11-15 by a Sonnet seat for Nate's app-wiring lead and checked by the lead (the example gate at `captures.ts:77` read again; the Search row and the sign-in step corrected); every row cites the file it rests on. Agent proposal where it orders work.

Short names used below. `E/` = `app/src/edge/api/`. `T:n` = `app/src/demo/types.ts` line n (the demo world's shapes follow the canon, so a screen's fields are those types). `Ex:` = an example name in `spec/examples/*.json`. `§8.n` = `spec/redesign/README.md` section 8, item n.

Two server facts that decide most cells:

- **Auth default is `user`.** `route()` sets `opts.auth ?? 'user'` (`app/src/edge/api/http.ts:106`). Only these are not user-auth: `visitor` = search, compare, products, products/history, trends, index/:id, out, jobs/:id, jobs/:id/events (each `+api.ts`); `none` = the six auth routes (`auth/*+api.ts`). `/v1/stream`, `/v1/today` and all the rest need a bearer token.
- **The example gate.** Every route built with `exampleHandler` (also the ones wrapped in `fromEngine(...)`) answers 404 "no example data for this user" to any user but `usr_8f2k`, unless its example is a visitor one (`E/captures.ts:77-78`). So a real new user, even with a token, gets 404 from: items list, plan-choices, items/sell, items/listings, conversations (3), orders (all 7), appointments, valuations, insights, goals, records, scores, assist, follows (4), experiments, sources/health. Routes on the runtime store (`engine(...)`, `E/runtime.ts:325`) do not have this gate: items/:id GET/PATCH, strategy, accounts, rules, limits, wants, matches/act, me, decisions, events, today, jobs, captures, search. `GET /v1/routes` lists each route's `source` (`E/routes.ts:39` lists why each example route is still an example).

## Sign-in, the large one

**What exists on the server** (`app/src/edge/auth.ts`, `E/auth.ts`, `E/me.ts`):
- Routes: `POST /v1/auth/apple`, `/google`, `/email/start`, `/email/verify`, `/refresh`, `/signout` (auth `none`); `/auth/link/{apple,google,email}` (user). Note the lead's brief said `POST /v1/auth/email`; the files are `email/start` and `email/verify` (`app/src/app/v1/auth/email/*+api.ts`).
- Apple and Google verify the provider ID token against the provider's JWKS (`auth.ts:132-137`), audiences read from env `APPLE_CLIENT_IDS` / `GOOGLE_CLIENT_IDS`. So a token can be issued for a real Apple or Google identity once those ids are set and the phone sends an ID token (whether they are set on the deployed server: unchecked).
- Access and refresh tokens, `POST /v1/auth/refresh` rotation by family, `GET /v1/me`, onboarding steps (`E/me.ts:9`).

**What is missing for a phone to get and keep a token:**
1. Email code delivery: `sendCode` is the no-op `logSend` (`auth.ts:247,250`), so `email/start` returns 202 but no code ever reaches an inbox.
2. No native Apple or Google sign-in on the phone: `app/package.json` has no `expo-apple-authentication`, Google sign-in or auth-session package (grep empty).
3. No token storage on the phone: no `expo-secure-store` or AsyncStorage dependency, and no `Authorization` header code outside the server (grep over `app/src`, excluding `edge/`). The client layer in `app/src/api/` does not exist yet, so its token seam is unchecked.
4. `app/src/you/sign-in.tsx:26-37` fakes sign-in with a 700 ms timer (any 6 digits except `000000` succeeds); `changed('session', ...)` is local state only (`signout-confirm` clears no session, §8 "Missing effects").
5. The auth store is process memory (`auth.ts:249` `memoryStore()`): every server restart signs everyone out; refresh then fails and the phone must sign in again.
6. Even a valid token for a new real user hits the example gate on the GATE routes above, so signing in unblocks only the runtime-store routes.
7. No refresh-on-401 loop on the client (client layer unbuilt, unchecked).

**Screens it blocks: 19 of 22** need a token for their main route: Today, Buy, Sell, You, Camera, New, Gone by, Item, Plan, Post, Ship, Pickup, Messages, Thread, Want, Worth, Onboarding (after sign-in), You pages, Site. The other 3 read signed out: Search, Product, Listing (their Follow, Watch, Offer and Bought acts still need a token). Of the 19, those that can show real data once signed in through runtime-store routes alone are Today, Want, Onboarding and Site; the others also wait on GATE or EX routes (Camera and New run on the capture routes, capture lead's).
