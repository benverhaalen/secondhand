## The one finding under all the others

The parts are built and tested one by one; the spine that composes them is not. `app/src/edge/intel/run.ts` (index first, hedged waterfall, single flight, streaming) is called by no route. `app/src/edge/harness/health.ts` (Beta health, breaker) and `app/src/edge/harness/session.ts` (lease, token-bucket pace) are not consulted by `createHarness` in `app/src/edge/harness/protocol.ts`, whose route chain is a plain loop. `createPool` in `app/src/edge/browser/pool.ts` is called only by tests. `POST /v1/search` (`app/src/edge/api/search.ts`) awaits `searchAll` to the end over a stub `fetchPage` that answers only one seeded eBay page, marks every row `relation: 'same_product'`, and finishes the job before returning it. ThriftX answers by live fan-out to six sites and Dupe streams its chat answer from a standing catalog ([Dupe observed](../../../research/watch/nate/dupe-observed-in-browser.md)); today our public search answers neither faster nor wider than either. Most of the ranked rows below are wiring, not invention.

### Where a model sits, and where it should not

- Right as specced: kind classification by rules first (intelligence-api §3.1), fees, limits and policy in code (product.md model allocation), the reply model wording only what code decided (`messages.ts` ports), `claim_check` deciding in code (`gate.ts`), the endpoint-or-page choice as a rule (protocol §3.3 step 2). Keep all of these.
- A model where a rule does better: none found in code. In the spec, `listing_swarm` specialist 4 (title terms per site) should stay a term count over winners in code, which the spec already implies; keep it that way.
- A rule where a model would add capability: rows 12 and 13 above, each as a typed head whose output code checks.
- The per-read path stays model-free on a warm template (rungs 1 and 2 of the extraction ladder); the only model on a search's hot path is Jev for the unresolved same-product band, one request per 20 results, at a 400 ms budget (`jev.ts`). That is the right shape for row 8.

### Cost per answer, for a five-site search (*inferred* arithmetic, starting values)

Plain-request lanes (eBay Browse, Poshmark) cost no browser time. Warm lane-2 pages cost under $0.002 a search at 100 searches an hour (row 2). Proxy bytes dominate: with images blocked, an assumed 0.5 MB per site page over two browser sites is 1 MB, $0.005 on the managed home-IP proxy at $5/GB or $0.0002 with `proxyCountryCode: null` at $0.20/GB ([cloud note](../../../research/cross-cutting/nate/browser-use-cloud.md#cost)). Models add 0 to 1 Jev request. So about a cent an answer with the managed proxy, a fraction of a cent without; measure bytes before choosing, as protocol §3.8 already says.

## What would most impress an AI engineering judge, buildable in a day

Four pieces, most already half-built, shown live in one sitting:

1. **The race**: one query, five sites, each site's batch landing on screen as it arrives with its seconds and its "What we considered" counts (rows 1 and 2 above). The benchmark's row 8 against ThriftX, run in front of them.
2. **The repair drill**: mutate a recorded Depop page (rename a field, nest it), watch `mutationDrill` in `app/src/edge/harness/repair.ts` produce a patch that passes the gate in three rounds or fewer, with the fixture untouched. No rival in [parity](../../parity.md) shows this.
3. **The glass box**: tap any decision, see its dossier, and replay it offline to the same verdict (row 9).
4. **The gate**: the eval and injection sets run in `node .agents/check.mjs`, a planted regression failing it (rows 8 and 11).

## What is already right and should not be touched

- The envelope and its eight codes with a typed `hint.do` (`protocol.ts` `HINT_DO`, checked at build time with `satisfies`); `parseEnvelope` at the trust boundary.
- Writes dry by default, a go per site, and a write that never switches route or replays (`protocol.ts` `call`, `sites/depop/adapter.ts` `write`).
- Empty is not broken (`classifyRead`, protocol §3.4) and a block that is final in `fetch.ts`: no rung routes around it.
- `solveCaptchas: false`, stop on every path, and a dropped CDP connection that still stops the cloud browser (`cdp.ts`); a stop failure handed to a sweep.
- The vault's compare-and-put and the rule that an empty state never overwrites a stored sign-in (`pool.ts` `dispatch`).
- Single flight that is not tied to one caller's abort, a failed call never cached, a hedge never sent to the same host (`run.ts`).
- `validateChoice` before any Jev answer runs anything, and the code default `unresolved` (`jev.ts`).
- `claim_check` deciding in code with the model only splitting text into claims, and abstaining on extractor failure (`gate.ts`).
- "Not found" as a fact with its `searched[]`, gathering before hiding, and the benchmark's rule that lost rows are published.
- The honest plain-request user agent in `fetch.ts`.

## Open questions only Nate or Ben can answer

1. **Is a 403 to a plain request a bot check?** `fetch.ts` treats a 403 as a block and never retries it on another rung, which keeps the "no bot check routed around" limit. Depop and Mercari answer a plain request with 403 and a cloud browser with a real page ([protocol §3.5](../../engines/protocol-and-adapters.md#35-starting-routes-site-by-verb)), and lane 2 exists for exactly that. If that 403 is the site's bot defence, lane 2 for those sites is routing around it. Nate decides which reading holds, per site; row 2 depends on it.
2. **Do the site's own web calls from inside its page count as private endpoints?** The Depop adapter reads `webapi.depop.com/presentation/api/v1/...` from inside the open page (`sites/depop/adapter.ts` `PATHS`), and protocol §3.5 says to try "the site's own data calls before driving controls". The fixed limits forbid private app endpoints. Nate decides whether the web client's own calls made from its own page are inside the line.
3. **Managed home-IP proxy or none for public reads?** It is the largest cost per answer (about 25 times the direct rate) and may change what sites answer. Nate's call on spend and on how it reads against "no proxy rotation".
4. **Which judge model and rubric are held constant for drafts and question planning**, and who the two human judges are for row 5 ([benchmark open](../../benchmark.md#open-for-nate-and-ben)).
5. **Whether the demo shows any write on a real account** ([product.md §8](../../product.md#8-cross-cutting-requirements) Account risk). Rows 5 and 6 can be proved on the fake site and a 7-day read-only soak without one.
