## What the table means

- **Search and pricing rows work today, signed out, on five sites.** Mercari is built and the adapter has read the site live, but the server has no Mercari route yet. Sold prices signed out come only from Poshmark today, and from Mercari once its route is composed. eBay's and Depop's sold prices need a linked account.
- **Monitor, manage and analytics are built on the four marketplaces and proved on none.** Every one of those verbs needs a signed-in account. No run with a linked account exists, so they are fixture-tested only. Depop's, Poshmark's and Mercari's signed-in paths have not been observed, so their fixtures are written by hand. eBay's monitor fixtures follow eBay's published API docs.
- **Every write runs dry.** By default a write returns its plan and sends nothing. With `dry: false` and no linked account, it asks for a relink. With a linked account, it hands the person the site's own page, because no submit has been observed yet (`depop/adapter.ts:332-338`, the same pattern on each site). Turning any write on needs Nate's go per site.
- **The next proofs, in order:**
  1. Compose the Mercari route in the server, so its live search and sold reads reach the product. This is a search-lead change.
  2. Link one account, Nate's, through the live view, then run each read verb once (inbox, offers, orders, stats) and record it here.
  3. Observe one real submit per site, still dry until Nate says so.
- Not covered here: Google Shopping (SR12, a Mac worker is building it) and the eBay API lane (no keyset).
