# How it works

These pages explain how the app works, in plain words, for a judge, a new teammate or a curious user. The [spec](../../spec/product.md) is different: it is written for the agents that build, and these pages tell the same design to a person. Nothing described here is built yet.

Read them in this order.

| Page | What it covers |
|---|---|
| [capture-to-facts.md](capture-to-facts.md) | How a few photos of an item become a list of facts, each pointing to where it came from. |
| [clarifying-questions.md](clarifying-questions.md) | Asking without questions: how unclear words are highlighted, and how a tap opens the right control instead of a question. |
| [identify-and-similar-items.md](identify-and-similar-items.md) | How the app works out what an item is and finds similar ones, such as cheaper alternatives. |
| [value-and-price-history.md](value-and-price-history.md) | How a value range is found from past sales, and how prices are tracked over time. |
| `how-we-price.md` | How the app picks a price to list at. |
| `how-we-market.md` | How the app writes and times a listing so the right buyers see it. |
| [selling-runs-itself.md](selling-runs-itself.md) | How one item becomes a listing on each site, and what the app does without asking. |
| [search-and-shopping.md](search-and-shopping.md) | How one search covers every store, how an official option is set beside a used one, and what a visitor and a signed-in person can do. |
| [how-we-prove-it.md](how-we-prove-it.md) | Why you can trust a number or message: kept evidence, hidden weak numbers, and checks before sending. |
| `how-we-compare.md` | How the app compares one choice with another, such as used against official. |
