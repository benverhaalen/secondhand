What it is

Databricks started as hosted Apache Spark, a way to crunch huge data on rented computers. Today one account holds your data, the computers that work on it, a normal Postgres database, app hosting, AI agents and a log of every AI call.

Think of a normal backend as five rented spaces from five companies, with five sets of keys and five bills. Databricks is one building: the stockroom, the shop counter, the staff and the ledger are under one roof with one key system.

The pieces we use

Each card: the real name, what it's like, and what secondhand uses it for.

Where things are kept

Delta tables

A spreadsheet with an undo history. Every change is logged, so you can read the table as it was last week, and every row gets a name tag that never changes.

For us: sales and listings we compare against ("comps"), facts about each item, events, rollups.

Volumes

The photo closet. Plain files, locked with the same keys as the tables.

For us: item photos, depth maps, saved copies of marketplace pages.

Lakebase

A normal Postgres database for the app, like the shop's cash register. It can copy itself in seconds ("branches"), sleeps when idle, and sends every receipt to the back office (Delta).

For us: the app's live state: items, listings, offers, jobs, your decisions.

Unity Catalog

The building's key system plus a family tree. It says who can touch what, and records what was made from what, without any code.

For us: permissions on everything, and lineage for "where did this number come from".

What does the work

Jobs, pipelines, SQL warehouse

Staff who clock in only when there's work. A job can start on a schedule, when a table changes, or when a new photo lands.

For us: processing photos as they arrive, keeping comps fresh, nightly rollups. Nate's health check runs on the SQL warehouse today.

Databricks Apps

A web server that lives inside the building, next to the data. Only people with a workspace login can walk in.

For us: the backend API (FastAPI). That login rule is why we need a small public "edge" in front (more below).

Agent Bricks

Databricks' way to host AI agents. The current path is code agents deployed with the Agent Bricks CLI. The older Knowledge Assistant and Supervisor Agent went legacy on 12 October.

For us: the agents that post, answer messages and follow up. Which runtime runs the long jobs (Agent Bricks, DBOS on Lakebase, or Flue) is still open. proposal: DBOS

Genie

A data analyst you can text. Ask in plain English and it writes the SQL over the tables you picked.

For us: "Ask" over your items and sales, and a public market space anyone can quiz. market space is a proposal

AI plumbing

Unity Gateway

One front door for every AI model, ours or a provider's. It handles budgets, fallbacks and rate limits, logs every call, and its policies can stop an answer before you see it.

For us: every model call goes through it. We'd add a check that each fact an AI states matches our records. proposal

MLflow 3

A flight recorder. It traces every step an agent takes, and "judges" score those steps afterwards.

For us: the "why?" timeline on every item, and your approve or edit taps become the labels that grade the agents.

AI Search

Finds things that are alike, by meaning and by keyword. It used to be called Vector Search.

For us: matching an item to similar sales. It embeds text only, so photo matching may go in Lakebase (pgvector). my read on the split

    They land in a Volume. A new file wakes up a job, so nothing runs while you're idle.

  3. It gets a price

What Nate set up

Nate made the Expo app (SDK 58, Expo Router), linked it to EAS, and connected it to the workspace. Right now the only screen is a placeholder that says whether Databricks answered.

Works

GET /v1/health runs one tiny query on the workspace's SQL warehouse and returns the catalog name and the time. Checked in a browser against the real workspace.

Works

No Databricks key on the phone. On a laptop the server borrows your Databricks CLI login (databricks auth login), so no token sits in a file. Every call goes through the shared logger.

Written

spec/databricks.md: Nate's full explanation of the platform and where every feature runs. He asked for it and said "Yes, push it".

Not yet

The Databricks App and Lakebase behind the edge. A hosted edge (it needs a service identity in its secrets). A run on a real phone or an EAS build.

Why the edge exists. A Databricks App only lets in people with a workspace login. It has no public mode in the docs. Our users, marketplace webhooks and visitors don't have workspace logins, so a thin public layer takes their calls and passes them in with its own identity. Think of a receptionist who signs guests into a members-only building.

Which workspace. Nate's first workspace looked like Free Edition (3 apps that stop after 24 hours, 1 Lakebase project, no GPU, open models only). When asked, Nate said "The event gives a full one", so those limits should go away.

Why we went all in, with a timer

  • Lakebase is the app database, synced to Delta. Unity Gateway calls the models.
  • MLflow traces every step, shown as a "why?" timeline on each item.
  • Your approvals are grading labels that move actions between "Ask" and "Auto".
  • Genie answers questions over your items and sales.

The reasoning

  • The judging rewards depth. Your words: "databricks is judging based on how well you use databricks platform / creativity sort of. its super general no clear criteria." MadHacks posts no Databricks rubric.
  • Past rubrics agree. DAIS 2026 asked "are Databricks capabilities used well?" and scored "Evidence and Uncertainty" as its own criterion. Bharat Bricks asked "Is Delta Lake/Spark actually doing work, or just present?"
  • The bar is low. In the winning repos Ben's research read, most used the platform thinly. Only one used Unity Catalog functions as agent tools with an MLflow eval run, and none used the Gateway, MLflow judges or pipelines.
  • The timer protects the demo. The app hosting and database are the riskiest parts: Lakebase logins expire every hour, Apps have no public door, and idle things take a moment to wake. my read on why 2 hours

What we add that Databricks doesn't have

Every fact keeps where it came from. Every number is cited, or it refuses to show. Every row carries what its source allows.

The gap: Databricks lineage goes down to tables, columns and file paths. It can't say which part of which photo produced "size M", or which exact sales produced a price. proposal, from Nate's spec

"Where did size M come from?"Tap it, see the photo with a box drawn on the tag, the model version, and "you confirmed".
A number that refusesAsk a thin question and it says "not enough sales" with the count. Ask a good one and it recomputes live from the sales it used.
A score that knows its limitsEach site gets four scores with a range. If a site changes its search, the visibility score hides itself and says why.

At the booth

Things you can say

"We're building secondhand. You snap an item, it works out what it is, prices it, and lists it on every marketplace. Databricks is the whole backend."
"Every number we show carries its sources, and it refuses to show when the data is thin."
"MLflow traces are a screen in our app. Every item has a 'why?' timeline."
"Your approvals grade the agent. Three clean approvals and it asks if it can just do that next time."
"We hit the wall where Apps need a workspace login, so a thin edge sits in front for the phone."

Good questions to ask them

Each one is an open question in our spec, so the answer helps the build. Tap for why it matters.

"For a consumer phone app, is a thin edge in front of an App the pattern you'd use, or is there a public way in?"

Apps only take workspace sign-in. A forum says anonymous calls get redirected. Our whole architecture leans on this.

"Lakebase tokens last an hour. What's your recommended way to keep a connection pool alive in an App?"

Tokens expire hourly and don't work through PgBouncer, and waking from sleep drops session state. This is part of the 2-hour timer.

"Can row-level security work for our app's users, who aren't workspace users?"

Row-level security keys on the database role, which is the app's. We'd carry the user's id ourselves.

"Can a Unity Gateway Python policy read a Unity Catalog table?"

That decides whether our fact checker can run inside the Gateway before an answer is released.

"Is row-level lineage on the roadmap?"

Lineage stops at columns. Our pitch fills that gap, so it's good to know if they're building it.

"Which image-capable models does this workspace serve, and can the Gateway sit in front of outside image models?"

Some hosted Claude models take text only on some workspaces. We need images for identifying items.

"For long agent jobs, would you use the Agent Bricks CLI or DBOS on Lakebase?"

The agent servers can run a tool twice after a crash. DBOS records each step so it doesn't repeat. This is open question J2.

"Genie Ontology went GA on 11 November. Is it on our workspace, and would you use it for a resale market?"

It's a learned map of business terms over metric views. It could power the public market questions.

"Has anyone aligned an MLflow judge to real user approve and edit taps?"

That's MemAlign. No winner Ben's research read did it, and it's our clearest "beyond the standard" piece.
