## 4. Decisions, and what waits on Nate

- One Store port, synchronous, file-backed for the one-container TestFlight period; moving to Postgres means an async port across every caller and is not started (the orchestrator, production audit).
- A dry plan is never a completed write: stage state `planned` (canon, §4), the site unchanged, the person asked.
- A delist after a sale is authorised by the confirmed order, never by the negotiation price rule.
- Writes are forced dry unless the site is named in `SECONDHAND_LIVE_SITES`; a write on a live account needs Nate's go per site.
- No vault file: sign-ins live in the person's cloud browser profile and the Store keeps only a profile id per account (the orchestrator's orc-session-1).
- The sweep budget is a param, prior 2000 sweeps a person a month (about $0.31 at the signed-in rate inferred from `product/roi.md`), and slows the lowest hazard first.
- Search sources are rows of data; a source failing fails only its stage; unresolved rows are kept and labelled, never dropped (Nate: the system always answers and says which fallback it used).
- Dupe is the first broad source: links exactly as given, `commercial_link` and `attribution` carried, nothing kept past the request, one search every 3 s.
- eBay public pages are read (Nate, "read ebay pages anyway"); eBay search runs through the harness page lane at 6 reads a minute; sold needs the person's sign-in.
- Waiting on Nate: one marketplace account signed in through the cloud live view (the first signed-in sweep); eBay developer keys; the email sender for sign-in codes; which rivals the benchmark names.

- `observation` is a Store table; `evidence` is the shape inside it (canon §2), not a table of its own. Observation rows are written under the asking person's `user_id` and read back for that person only; pooling public rows across people is a later, separate decision. Dupe rows are never written.
- The valuation route prices the person's own item; another person's item answers `not_found`, never an example. The example item stays only for the example user.
- With no client address bound by the host, the visitor limit keys by the visitor id, never one shared bucket: a shared bucket would throttle every visitor at once.
- System work (the watcher, the scheduler) gets its own cross-person account lookup; every request-reachable path is person-scoped.
- Which server the phone calls: the screens read in-app demo data; only `want.tsx` (`/v1/stage`) and `dev/health.tsx` fetch, by relative URL. That reaches the Expo dev server from a dev client on the same LAN, and nothing from a standalone build (no expo-router `origin`, nothing hosted). Hosting is public and Nate's decision; the orchestrator has taken it to him.

## 5. Learned the hard way

- Squash or reset only onto an explicit commit id. A `git reset --soft origin/main` in a Mac worktree picked up a ref another worker's fetch had just moved and reverted two files from another session (79e20adc, restored in 5b95a9e5).
- A check that parses code by counting braces is wrong on TypeScript: the bundle check read the `{` of a return type such as `Promise<{ ok: true }>` as a function body and reported three false top-level awaits in the Depop adapter, turning main's check red. Parse with the TypeScript compiler.
- A benchmark time is only as fine as how it is read: the runner stamped first-answer when its 2 s poll saw results, so every time was rounded up to 2 s. Read the job's own stage clocks.
- Evidence must be what was read, not a second fetch: the saved Poshmark page parsed cleanly, so the miss it was meant to explain is still unexplained.
- The copied API test "wrong user cannot read example data" asserts 404 on every route for every other user; a real engine route must let a new person create and list their own, so two workers built a product where only the demo user could use collections until it was caught.
- A chain like `tests && commit && push` pushes past a failing test when the failure only shows in printed output; read the counts before the commit, not after.
- A Codex worker's sandbox makes `.agents/` read-only and blocks a local listener and `git merge`: stage check code under `scripts/<piece>-staging/`, run listener tests yourself outside the sandbox, and merge `origin/main` into a worktree yourself before an `AGAIN=1` follow-up.
- Fresh review found what the workers' own reviews did not, twice: a like reaching `answer_offer` with no amount, and the delist gated by price. Every merged piece in this area still has an unticked board row until a fresh reader passes it.
- Main went red in this area from changes elsewhere: the identity engine's import style broke the walk's Python bridge, and the param registry's new forgetting rule broke a test that pinned the old one. After any merge of main, rerun this area's tests and the real-time proof.
- A pin in a test changes in the same commit as its cause. Turning eBay on in 5d56f159 moved the proof's source pin, which had to be fixed in a follow-up (99bde8cf).
- Two of three workers' first rounds passed their own tests and still broke the composed product: a person-scoped `byId` starved the watcher's relink, and a limiter with no bound address shared one bucket across every visitor. Read every caller of a changed function, and ask what the composed runtime passes, not only what the tests pass.
- A pace slot taken before a route that cannot run turns a free `no_route` into a 10 s wait (J12, likely). Check whether a source can run before it waits.
- Rewriting a doc by shifting off its first line can drop a heading that shared that line: `joins.md` had a mangled first line with the title at its end.
