The wiring, use-search.ts:
  useSearch() -> { reach: Reach | null; failure: ApiFailure | null; run(text: string): void; stop(): void }.
  run(text): aborts any search in flight, calls api.search(text), then api.jobFrames(id, { signal, onFrame }), keeps the 202 body and every frame, and sets reach = reach(start, frames) after each frame. A failure of either call sets failure (reach stays as it was). Unmount aborts. Log through log from '@/ui': the search started (query length, not the text), each frame's event name and id, a failure with its code.
  Put the fold in a pure function exported from the same file, e.g. fold(state, action) for start, frame, failure and reset, and test it with the recorded fixtures: frames applied one by one give the same Reach as reach(start, frames) at every step; a new run discards the old frames; a failure after three frames keeps those three.

The look, search-reach.tsx: <SearchReach reach={reach} failure={failure} onRetry={...} onOpen={url => ...} />.
  - Above everything, one line of counts, each a field of Reach: sources answered of sources asked (landed.length of sources.length), listings read and kept (found.results_found, found.results_used), and once settled the time to first rows and to the full answer (ms.first, ms.settled, as seconds to one decimal).
  - One ListRow per source in sources order, from the first frame: a marketplace in SITES gets its logo (site), any other source (dupe) a lead icon and its name capitalised. The detail line says, for the row's state:
      running: asking
      arrived with kept > 0: "<read> read, <kept> kept", then each dropped reason with its count ("18 duplicates")
      arrived with read 0 or outcome empty: nothing for this search
      outcome needs_account: needs your account
      failed: the server's error in plain words by code (no_route: not connected here; blocked: refused us; page_changed or unknown: couldn't read the page; anything else: couldn't search), tone brick
      late: too slow, left out
      cached refreshing: saved copy, checking again; cached kept: saved copy
    and the value is the source's ms as seconds to one decimal once it has landed. Keep every word minimal and lowercase where the part's style is; the designer will rewrite them, so put every string in one object at the top of the file.
  - Results: one ListRow per result (title as label, the price as value from delivered_cents or price_cents, formatted with money from '@/ui', the source site as detail), pressing it calls onOpen(url). While state is running the section title marks them as so far; after settle it does not.
  - state failed or a failure: EmptyState with what did not load and Try again (onRetry). No rows invented.
  - The screen root names itself for the gallery and the e2e (dataSet screen 'dev/search', state from Reach: new, running, done, failed), as other screens do through <Screen name state>.
  No animation beyond what the parts already do. Motion, layout and words are the designer's.
