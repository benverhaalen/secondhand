What client.ts exports (names are yours to refine, the behavior is not):
  - createClient({ origin, fetch, now? }) returning { call, search, jobFrames, session }. A default `api` built from origin.ts and fetch.ts is exported too, so screens import one thing. Tests build their own client with a fake fetch; no test touches the network or globalThis.fetch.
  - session: { token: string | null; visitor: string | null }. token stays null (sign-in cannot issue one yet); when set, every call sends Authorization: Bearer <token>. visitor is taken from the X-Visitor-Id header of any answer and sent on every later call, because GET /v1/jobs/:id/events only answers the visitor that made the job (a different visitor gets not_found). Memory only; no storage yet (say so in a `shortcut:` comment).
  - call<T>(endpoint 'POST /v1/search' style or method+path, { body?, signal? }) -> Promise<T>. A non-2xx answer throws an ApiFailure (exported class) carrying status and the server's code, message and retry when the body has them; a network error throws ApiFailure with code 'unreachable' and status 0. The result is typed by the caller; parsing the shape is the caller's job.
  - search(text, filters?) -> the 202 body, typed from the server by `import type` (do not copy server types): the stages are `SearchStage` from app/src/edge/api/search.ts. Import types only (`import type`), never server values: the server modules pull node-only code.
  - jobFrames(jobId, { signal, onFrame }) -> Promise<void>: opens GET /v1/jobs/:id/events with Accept: text/event-stream, decodes response.body with getReader() and TextDecoder({stream:true}), feeds sse.ts, and calls onFrame for each frame in order. If response.body is null, it reads response.text() once (the stream ends with the job, so that still gives every frame, only late). If the connection drops before a job.state frame whose state is done or failed, it reconnects with Last-Event-ID set to the last frame id, at most 3 times, then throws ApiFailure 'stream_lost'. Aborting the signal ends it quietly. Frames are typed as SseFrame from app/src/edge/api/jobs.ts.

What sse.ts exports: a pure incremental parser. createSseParser() -> { push(chunk: string): SseFrame[] } that holds a partial block across chunks, ignores ':' comment lines (heartbeats), accepts \n and \r\n, joins multiple data: lines with \n, parses data as JSON (a block whose data is not JSON is skipped and counted in a `skipped` number, never thrown), and takes id as a number.

Failure modes to test first, each named so its failure says the cause:
  - a frame split across two chunks, and a chunk holding three frames and half of a fourth
  - heartbeat comments between frames produce no frame
  - \r\n line endings
  - the whole recorded fixture, encoded back to SSE text and pushed in 64-byte chunks, gives back exactly fixture.frames in order
  - the visitor id from the first answer's header is sent on the next call; a token, once set, is sent as Bearer
  - a 400 with the server's error body throws ApiFailure with that code and retry; a rejected fetch throws code 'unreachable'
  - a stream that ends after frame 5 of the fixture without job.state done reconnects with Last-Event-ID 5 and gets the rest; three drops in a row throws stream_lost
  - a null body falls back to text() and still yields every frame
  - an aborted signal stops without throwing and without reconnecting
  - origin.ts returns EXPO_PUBLIC_API_ORIGIN when set and '' when not
