How the frames work (from search.ts; confirm in the code):
  - The 202 body (`start`) lists every source asked as a stage `site:<id>`, state running, in the order asked. That order is the order the screen lists sources.
  - Each source lands with job.stage {stage, state: arrived | late | failed, at, found, error?} immediately followed by answer.partial {site, results (that source's ranked offers), sites_pending, answer}. answer.searched[] has one entry per source landed so far, each with site, route_id, outcome (a SiteOutcome: hit, empty, blocked, timeout, page_changed, needs_account, failed, unknown), ms, and when present pace, dropped (unreadable cards), error_code, reason, fallback, cost_usd_est.
  - A source served from cache lands twice: first while its id is still in sites_pending (that is the saved copy; a refresh is running), then again with the live read. answer.settled's searched[] marks it cached: true when the live read did not replace it.
  - needs_account is an arrived stage with no error; only answer.searched says needs_account and its reason.
  - answer.settled carries the merged ranked results and the merged found (cross-source duplicates removed), then job.state done. job.state failed carries error {code, message}.

What reach.ts exports:
  reach(start: unknown, frames: unknown[]): Reach   pure; parses at the boundary; a frame it cannot read is skipped and counted in reach.skipped, never thrown and never guessed at.
  Reach = {
    state: 'running' | 'done' | 'failed';
    query: string | null;                      // answer.slots.text of the newest answer
    sources: SourceReach[];                    // in the order of start.stages
    landed: string[];                          // source ids in the order they first landed
    pending: string[];                         // newest sites_pending, else every source not yet landed
    found: Found;                              // answer.settled's found once settled; before, the sum of each source's newest stage found
    ms: { first: number | null; settled: number | null };   // newest answer.ms
    results: OfferView[];                      // settled: answer.settled results in its order; before: each landed source's newest partial results, sources in landing order
    error: { code: string; message: string } | null;        // job.state failed
    skipped: number;
  }
  SourceReach = {
    id: string;                                // the stage name without 'site:'
    state: 'running' | 'arrived' | 'late' | 'failed';       // the stage state
    outcome: SiteOutcome | null;               // from the newest answer.searched entry for this site; null until it lands
    read: number; kept: number;                // found.results_found, found.results_used
    dropped: { reason: string; count: number }[];           // found.dropped_by_reason, largest first, then by reason
    ms: number | null; pace: Pace | null; cost_usd_est: number | null; fallback: 'apify' | null;
    cached: 'refreshing' | 'kept' | null;      // refreshing: landed while still pending; kept: settled searched says cached
    error: { code: string; reason: string } | null;        // stage error, else searched error_code and reason
    at: string | null;                         // stage at
  }
  Use the server's names for states and outcomes; invent no new word for a state the server has. A source with no frame yet is running with zeros and nulls, exactly as the 202 says.
