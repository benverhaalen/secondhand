# Corrections

Open when: he corrects anything about a UI (an explicit "no", an edit to a file you wrote, a repeated nudge, a revert, a rejected image). Read before acting: `.agents/vendor/emil/learn-taste/SKILL.md` (its five signals, its filter tree, its generalization levels and its "A check beats a sentence").

1. Record the correction at once with his exact words (the record's heard ledger via the core hook, and `brand/corrections.md`).
2. Take it as taste the agent lacked, generalized to the class of thing (learn-taste's "Class" level), never to everything and not to the one instance.
3. If a script can check it, offer it through the `lint-rule` skill as a check, with the same ratchet. If not, offer it as a rule with its reason, for the one place in the brand file where it belongs; if a rule already covers it and failed, rewrite that line stricter rather than adding a second (Kite's one rule, one place).
4. Write the reason you inferred, marked as your reading. Do not ask him to justify taste in words; asking for reasons can degrade taste signals (eliciting-from-his-head.md:9).
5. The next reply shows the offered rule or check and where it would go, with yes and no buttons. It becomes standing only on his yes. Work goes on while the offer waits; this is not a stop.
6. A correction that conflicts with something he approved, or with a brand code: show a picture pair before changing it (the old skill's rule: return with a comparison instead of silently changing style).
