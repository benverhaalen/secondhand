# Databricks coverage map

Date: 2026-11-15. Agent draft for Nate, who asked: "focus on ensuring databricks works, that we've accounted for everything fully planned and currently being built that alligns with the product".

How it was made. I read `spec/plans/finalization.md`, every `features/*/README.md`, every `spec/engines/*.md`, `spec/data-use.md`, the lakehouse files (`databricks/sql/*.sql`, `databricks/pipelines/market/*.sql`, `databricks/tasks/*.py`), the bundle (`deploy/databricks.yml`, `deploy/resources/*.yml`, `deploy/tasks/*.py`) and the fits (`jobs/*/`). Nothing was run: no Databricks call, no server, no network.

The rule: every cell rests on a file I read and cites it as a repo path. "none" means I looked and found nothing. "(inferred)" marks my reading, not a file's words. Names after "Missing" are proposals, not tables that exist.

What the lakehouse holds today, from the files: catalog `secondhand`; schemas `core` (observation, evidence, citation, guarded_number, claim_check, param, event, job, decision, storefront_snapshot, log_event: `databricks/sql/01_tables.sql`), `governance` (principal_map, break_glass, source_rights, erasure: `02_governance.sql`, `11_sources.sql`, `12_erasure.sql`), `measures` (recompute, backtest, bench, guard, why and dashboard views: `03_measures.sql` to `14_engine.sql`), `market` (comp pipeline, `comp_for_product`, the DBX-A1 views and functions: `pipelines/market/*.sql`, `15_market.sql`), `raw` (volumes landing, captures, snapshots: `00_layout.sql`). Per-person app state (item, capture, photo, conversation, message, offer, sale_receipt, label, offer_outcome, param, route_table and more) lives in Lakebase: `db/migrations/0001_base.sql` to `0004_param.sql`. I found no Lakebase-to-Delta sync in `databricks/` or `deploy/` (inferred from absence).

## Rows this adds to the Databricks plan

All are *agent proposal*. DB0 to DB8 are in `spec/plans/finalization.md` section 5. Each proof is a command that can be run offline unless it says "workspace".

1. **DB9, a rights row per live source.** Add rows to `databricks/sql/11_sources.sql` for Poshmark, Mercari, Depop and eBay page reads, Facebook through Apify (`may_store` true, `may_model` false, `may_model_scope` hackathon_demo, `may_show` true), and official retail; make `load_observations.py` refuse a line whose row rights are looser than its source's. Proof: a new case in `databricks/tasks/test_load_observations.py` where an Apify line with `may_model` true is refused, and `measures.model_clearance` lists every live site.
2. **DB10, a retention sweep.** A daily job that deletes `core.observation` rows past `keep_until` or past the source's `ttl_hours` and their evidence (`appendOnly` is already off: `databricks/sql/08_constraints.sql:60`). Proof: a test with one expired row and one live row; after the run only the live row is counted in `market.coverage`.
3. **DB11, the nightly fits that run.** Eight of nine tasks in `nightly_fits` (all but `valuation`) are skipped because `jobs/<engine>/learn.py` and `fit.py` have no `main()`, and `jobs/person/fold.py` is never found by `deploy/tasks/fold.py`. Give each a `main()` that reads only what it may model on and writes through the registry; add `capture` and `photo` tasks; keep the job PAUSED until Nate's yes (DB8). Proof: `deploy/tasks/test_purge.py`-style test that `fold.run(engine)` returns `ran` or a stated skip reason for all eleven engines, none silently `no main()`.
4. **DB12, the brand job.** A task that reads `market.listing_obs`, builds the attribute record, runs `jobs/measures/brand_premium.py`, and writes `core.param` name `brand_premium` by explicit columns, skipping with the counts when either side is under `brand_premium_min_side`. Proof: `jobs/measures/test_brand_premium.py` plus a fold test on a seeded `listing_obs`.
5. **DB13, per-person data in Delta: Nate's scope call.** Today messages, offers, orders, listings, labels and `offer_outcome` live only in Lakebase, so `insights`, platform analytics, negotiation and trust cannot fit in the lakehouse.
